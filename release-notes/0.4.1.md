The agent no longer gets stuck. Seen in a real session on a 9B model: one `grep_vault` call repeated 60 times with identical arguments, 150 `read_note` calls guessing every calendar date in `Daily Notes/` (60 % of them misses), and a regular expression sent as literal text that found nothing and turned into a false "there are no code snippets to move".

**Reliability**
- Repeated-call guard: a read-only tool called again with exactly the same arguments in a turn is not run; the model is shown the earlier result and told to do something else. At the third repeat the turn ends with a wrap-up answer instead of burning the whole call budget. The guard forgets everything after a write, so a re-read after an edit sees the new content.
- `grep_vault` recognises a regular expression sent with `regex: false` (`^\s*>`, `a|b`, `[A-Z]`): when the literal search finds nothing it searches as a regex and says so. Spaces around `|` are trimmed.
- A path that does not exist now returns the notes that *do* exist in that folder (all of them for a small folder, the nearest by name for a large one), or the folders that exist and similarly named notes, so one miss teaches the model the folder instead of inviting the next guess.
- `list_notes` shows each note's size, so empty template notes can be skipped without reading them.
- Prompt: never guess paths; survey one section across many notes with a single `grep_vault` call with context; a search that finds nothing is the answer for that pattern; "messy", "empty" or "long" are structural questions for `list_notes`, `list_sections` and `grep_vault`, not for semantic search.
