A release about the first five minutes and about trust: a setup checklist, sample notes to try it on, a problem report you can read before it goes anywhere, other local servers besides Ollama, vaults of 50,000 notes, and tests that run in a real Obsidian.

**Getting started**
- **Setup checklist.** The first time you open the chat (and from the command or settings): is the server reachable, is there a chat model that can call tools, an embedding model, an index, each with a fix button. Missing models are downloaded through Ollama with progress; the recommended model follows the machine you pick (24 GB, 12–16 GB, 8 GB GPU, or none).
- **Try it on sample notes.** Creates a small folder of five linked notes and offers three questions, so you see a cited answer within a minute of installing.

**Report a problem**
- **A command, a settings button, and a link on every error.** It writes the GitHub issue for you (versions, operating system, model names, settings, index statistics, the last 50 log lines) and shows it for you to read and edit. *Copy* or *Open on GitHub*; the plugin itself sends nothing.
- **What never goes in:** API keys and tokens, URL query strings, e-mail addresses, your extra instructions, the vault's path and your home folder (shown as `<vault>` and `~`), note contents, and chat text unless you tick *Include the last chat*.

**Other local servers**
- **LM Studio, llama.cpp server, Jan, vLLM** through their OpenAI-compatible API (`/v1/chat/completions` streamed with tool calls, `/v1/embeddings`): *Settings → Provider*. Ollama stays the default and is what the benchmark measures. The plugin's own API reports the provider in `api.ollama()` as an added field.

**Languages**
- **Answers in your language**: the language of the question by default, or one you set. The chat, settings, command names and the main dialogs read their strings from one dictionary (English complete), so a translation is one more file; most notices and the older dialogs are not moved yet.

**Large vaults**
- **The index is stored in shards and built without quadratic work.** On a generated 10,000-note vault the plugin's own share of the first index went from 134 s to 1.6 s, and editing one note rewrites 4 MB instead of 125 MB; a 50,000-note vault, which 0.7.0 could not have saved at all, indexes with 10 s of overhead and answers a semantic query in 0.28 s. Existing indexes are moved over without re-embedding.
- **The vault outline and the Vault suggestions report no longer slow down with the square of the vault** (backlinks from one reverse map; mentions by a name's rarest word): suggestions on 10,000 notes take under a second.
- Numbers, method and what they do not cover (the embedding model's own time, Obsidian's caches) are in the README under *Large vaults*.

**Reliability**
- **A write is one whole note or nothing.** Approving a diff after pressing Stop writes nothing; a note that changed while its diff was open is not overwritten; a failed write is not recorded and leaves the note as it was.
- **A message that fails or is stopped part-way** says how many changes it had already applied and offers to undo them all.

**Quality**
- **Lint is at zero warnings** with the Obsidian review rules: settings use the declarative API (so they show up in Obsidian's settings search on 1.13+), plain requests go through `requestUrl`, and only the streamed replies use `fetch`.
- **End-to-end tests in a real Obsidian** (wdio-obsidian-service, a scripted stand-in for Ollama): chat → diff → approve → note changed, reject, undo, the change history, and the problem report. They run in GitHub Actions on every change; the workflow fails unless all six pass.
- **Keyboard and screen-reader work**: labels on icon buttons and inputs, a live region for the conversation, visible focus rings, a focusable diff, larger touch targets on phones.
- **Beta channel** for BRAT testers: pre-releases from `manifest-beta.json`; the store's `manifest.json` is untouched by a beta.
- **One feedback question**, once, after the fifth answer; its buttons only open a GitHub page.
