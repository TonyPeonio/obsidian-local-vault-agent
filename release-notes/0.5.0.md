Four new things to do with the agent, measured benchmarks, and a model that no longer talks itself into loops.

**New**
- **Process my daily notes.** One command (or `/daily`) that surveys the inbox section of every daily note, compiles the substantial ones into topic notes with links back to the source days, collects code blocks into a snippets note, and replaces each compiled inbox with `- Moved to [[Topic]]` so the daily notes stay timelines. Options dialog for the folder, heading, destination, look-back and whether to move; every write is diff-approved.
- **Edit the selected text with an instruction.** Select a passage, run the command (or `/edit`), type "make this a table" or "past tense", approve the diff. The agent edits exactly the passage you selected.
- **Suggest vault improvements** (`/garden`). A deterministic pass, no model needed, that writes a *Vault Suggestions* checklist note: broken links, daily inboxes that filled up, notes mentioned by name without a link, near-duplicate notes (from the semantic index), orphans and stubs. Each section says what to ask the agent to fix it.
- **Test connection and speed.** The settings button now also runs a short generation at your context size, reads how much of the model is on the GPU versus in RAM, and gives one-line advice with buttons: use a larger context when there is room, a smaller one or a smaller installed model when it is spilling. Flags a chosen model that cannot call tools.
- `replace_section` tool: rewrite or empty everything under a heading without copying its old text.
- `list_sections` surveys one heading across notes: `heading: "Capture"` lists that section of every daily note with its size and first line, so "which daily notes have a full inbox" is one call instead of 120.

**Measured**
- `npm run e2e:large` is now a scored benchmark: 14 scenarios on a 339-note synthetic vault (questions, enumeration, clean-ups, moves, the daily-notes job, and the loop failures seen in a real vault), each timed and counted for tool calls, errors, guessed paths and repeated calls; results are saved to `bench/<version>.json`. The README carries the table.

**Fixed**
- Sampling: temperature 0.6 with top_p 0.9, top_k 20 and a small presence penalty, per the Qwen3 model card, which warns that near-greedy decoding causes endless repetition. Users still on the old 0.3 default are moved; a changed value stays.
- The system prompt is built once per turn instead of once per step, so Ollama's prefix cache is hit on every step of a long task even after a write (before, every write invalidated it).
- `grep_vault` also recognises escaped metacharacters (`!\[\[Recording`) as a regex sent by mistake with `regex: false`.
- When a long task fills the window and an earlier tool result is shortened with "call the tool again if you still need it", calling it again is allowed; 0.4.1's repeated-call guard refused it and could end the turn early. Found by the benchmark's clean-up scenario.
- After a write, the guard forgets only reads of the changed note and vault-wide results (grep, lists, searches); re-reading an untouched note "to verify" is refused with the earlier result, which is where a 9B model spent half of a clean-up's time.
