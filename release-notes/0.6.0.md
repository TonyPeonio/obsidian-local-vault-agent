Vault suggestions move into the chat and stop needing the model, and a new message no longer re-reads the whole prompt.

**Vault suggestions (`/garden`)**
- **Nothing is written to the vault.** The report is a chat message with plain bullets; the *Vault Suggestions* checklist note is gone, because its open checkboxes showed up in every task query over the vault. If an earlier version left that note behind, the report offers to move it to the trash.
- **The mechanical fixes run without the model.** *Repoint moved links*, *Link mentions* and *Remove identical copies* are worked out by the plugin: the same diff dialog as an agent edit (with *Approve all*), done in about a second, undone with `/undo-all`. Asking a local 9B model to do this took ten minutes of reading notes it did not need to read. Only *Review similar notes* and *Suggest links for orphans* still ask the model, and only for a proposal.
- **A broken link says whether its target moved.** `[[Old folder/Note]]` is reported with where the note is now when exactly one note or file has that name; those are the links the button repoints.
- **Fewer false findings.** A mention has to be a distinctive name: several words, or one word that could not be an ordinary one (`GenKIC`), with capitalised names matched as written; never a note the page already links to, or the note its own folder is named after. Duplicates are identical copies (found without the index; frontmatter and the folder inside a wikilink do not count as a difference) or notes that share at least half their lines, not everything the embedding index calls similar, which included every lecture built on the same template and slide deck. A note that is one query block or one embed is not a stub, and the conventions note is not an orphan.
- **Prompts sent by a button no longer attach every note they name**, which had added tens of thousands of characters the model then read a second time.

**Speed**
- **A new message starts from the cached prompt.** The date, the open note and today's daily note moved out of the system prompt into a line sent with your message. Ollama reuses what it has already read only up to the first difference, and the system prompt comes first, so opening another note between two messages used to mean re-reading the outline, the tool list and the conversation. On a laptop with an integrated GPU (Ryzen 7940HS, Radeon 780M, `qwen3.5:9b`) the wait before the first token of a second message went from 58 s to 1 s.
- **Only changed chunks are embedded again.** A note that grows a paragraph at a time (a lecture being transcribed, a daily note being typed) had every chunk re-embedded on each save; now only new or edited chunks go to the embedding model, and an edit is picked up after ten seconds of quiet instead of two.
