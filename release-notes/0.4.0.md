Reliability on big vaults, and the agent behaves more like a coding agent.

**Reliability**
- Context guards: when a long task fills the window, older tool results from the same turn are shortened (the system prompt and your request are never pushed out), a single batch of tool calls is capped, and a blank reply is nudged once. Found by running a 330-note synthetic vault.
- `grep_vault`: grep across every note, each match tagged with its enclosing heading, optional context lines.
- `edit_notes`: many edits across many notes in one call, one approval per note — a clean-up found with grep becomes two or three steps.
- At most 8 tool calls run per step; the rest are refused with a hint to grep instead of reading everything. The prompt tells the model to use it instead of reading every note to find something.
- Outline lines name the file explicitly, and tools tolerate a path copied with outline decorations.
- Backticked note paths in replies become clickable wikilinks.

**Speed**
- Re-reading an unchanged note within a turn is short-circuited.
- Readable tool cards ("Searched passages for …", "8 results") and a live "3 tool calls · 42 s" status while a turn runs.

**Capabilities**
- `read_file` extracts the text of PDFs (Obsidian's pdf.js) and text attachments.
- `list_notes` filters by `modified_after` / `modified_before`.
- Today's daily note (per the Daily Notes core plugin settings) is named in the system prompt.
- `edit_notes` items can address a line by `line_contains` within a `heading`, so clean-ups need no exact copying.
- README documents measured context/VRAM/speed numbers for 32k–128k windows with q8_0 KV cache.

**Polish**
- Approval dialog: Enter approves, A approves all in this chat, Esc rejects.
- The chat is saved and restored across panel closes and restarts; New chat clears it.
- One notice per session when Ollama or the chosen models are not available.
- Default max tool calls per message raised to 60.
