Reliability on big vaults, and the agent behaves more like a coding agent.

**Reliability**
- Context guards: when a long task fills the window, older tool results from the same turn are shortened (the system prompt and your request are never pushed out), a single batch of tool calls is capped, and a blank reply is nudged once. Found by running a 330-note synthetic vault.
- `grep_vault`: grep across every note, each match tagged with its enclosing heading, optional context lines.
- `list_sections`: per-section yes/no flags for up to four texts ("which lecture sections have a recording but no Summary") without reading anything.
- `edit_notes`: many edits across many notes in one call, one approval per note; items can address a line by `line_contains` within a `heading`. A clean-up across 60 lecture sections is now two tool calls (measured: 17/18 embeds removed, none wrongly, 115 s on a 9B model; before: 0/18 and a full context window).
- At most 8 tool calls run per step; the rest are refused with a hint to grep instead of reading everything. The prompt tells the model to use it instead of reading every note to find something.
- Repeated-call guard: a read-only tool called again with exactly the same arguments in a turn is not run; the model is told what the result was and to do something else. At the third repeat the turn ends with a wrap-up answer instead of burning the whole call budget (seen in the wild: one grep repeated 60 times).
- `grep_vault` recognises a regular expression sent with `regex: false` (`^\s*>`, `a|b`, `[A-Z]`): when the literal search finds nothing it searches as a regex and says so. Spaces around `|` are trimmed. Before, "no note contains" became a false "there are no code snippets".
- A path that does not exist now returns the notes that *do* exist in that folder (all of them for a small folder, the nearest by name for a large one), so one miss teaches the model the folder instead of inviting the next guess (seen: 150 reads of `Daily Notes/<every date>`, 60 % misses).
- `list_notes` shows each note's size, so empty template notes can be skipped without reading them; the prompt explains surveying one section across many notes with a single `grep_vault` call with context, and that "messy / empty / long" are structural questions for `list_notes`, `list_sections` and `grep_vault`, not for semantic search.
- Outline lines name the file explicitly, and tools tolerate a path copied with outline decorations.
- Backticked note paths in replies become clickable wikilinks.

**Speed**
- Re-reading an unchanged note within a turn is short-circuited.
- Readable tool cards ("Searched passages for …", "8 results") and a live "3 tool calls · 42 s" status while a turn runs.

**Capabilities**
- `read_file` extracts the text of PDFs (Obsidian's pdf.js) and text attachments.
- `list_notes` filters by `modified_after` / `modified_before`.
- Today's daily note (per the Daily Notes core plugin settings) is named in the system prompt.
- README documents measured context/VRAM/speed numbers for 32k–128k windows with q8_0 KV cache.

**Polish**
- Approval dialog: Enter approves, A approves all in this chat, Esc rejects.
- The chat is saved and restored across panel closes and restarts; New chat clears it.
- One notice per session when Ollama or the chosen models are not available.
- Default max tool calls per message raised to 60.
