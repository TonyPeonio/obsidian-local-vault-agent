Faster turns and a far shorter first index, with the same benchmark score.

**Why it was slow.** Two things compounded. The history the agent carried per step grew with the context window, so at a 96k window a long session reached 60k tokens; and once over budget the trimmer reshaped older messages on every step, which invalidated Ollama's prefix cache, so each step re-read the whole conversation. On a 12 GB card a 9B model at 96k also leaves no room for the embedding model, so Ollama evicted one to load the other on every search, reloading the chat model each time.

**Changed**
- **History is capped at the 32k budget** whatever `num_ctx` is set to (the benchmark scored the same at 32k and 64k), and finished turns are compacted once when a new turn starts instead of being reshaped on every step: reasoning dropped, old tool results cut to 400 characters, oldest turns removed. Within a turn the messages sent to Ollama are append-only, so the prefix cache holds and each step prefills only what is new.
- **A context window above 32k is brought back to 32k once** by the settings migration (set it again if you have the VRAM); the setting's description now explains the trade-off.
- **Gists are off by default.** The pass runs the chat model once per note; on this card that was 230 s for the benchmark vault and bought one check, on a laptop GPU with a large vault it is the better part of an hour. The embedding index that search depends on is unchanged and stays on. Existing installs with gists on are switched off once; the toggle turns them back on.
- **Embedding batches of 64 passages** instead of 16 (same speed per passage on a GPU, a quarter of the round trips on a CPU-only machine).
- **The plugin tells you when the model is spilling into system RAM.** After a turn it checks Ollama's `/api/ps`; if the chat model is only partly in VRAM, one Notice says how much and what to do (a smaller window or `qwen3.5:4b`).
